Comb Language Reference

.comb files declare signals, derived values, state transitions, and views in a single module. The compiler extracts a static dependency graph (__graph), verifies it, and emits readable JavaScript.

Why Comb?

Every reactive framework has a dirty secret: your dependency graph is invisible. You can write computed(() => a.value + b.value) in Vue or a useMemo in React, but neither framework can tell you what depends on what at build time. The graph exists only at runtime, scattered across closures and hook slots. You can't query it, diff it, or verify it. When something goes wrong, you reach for browser DevTools and add console.log statements until you find the broken link.

Comb's compiler does something no other framework does: it extracts the complete dependency graph as a static data structure at compile time. Every signal, comb, cell, event handler, view binding, and assertion becomes a node. Every dependency becomes an edge. The result is a JSON object called __graph that ships alongside your JavaScript — not as a debugging aid you opt into, but as a first-class build artifact that's always there.

This one decision unlocks things that are structurally impossible in other frameworks. You can render a live circuit diagram where signals pulse through wires in real time (the playground does this). You can diff two versions of a component and see exactly which dependencies changed. You can write assert canSubmit_valid: canSubmit == (usernameOk && emailOk && passwordOk) and the compiler will verify the assertion's dependencies are a subset of the formula's dependencies. You can build a waveform debugger that plots signal values over time, like a logic analyzer for your UI. None of these require special tooling or plugins — they fall out of __graph for free.

The insight comes from hardware design. In SystemVerilog, every wire and register is declared, every connection is explicit, and the synthesis tool can verify timing constraints before the chip is fabricated. Comb applies the same philosophy to UI: every reactive primitive is declared with its type and initial value, every dependency is extracted statically, and the compiler can catch entire categories of bugs (misspelled dependencies, circular definitions, self-triggering writes) that other frameworks only discover at runtime. The <= operator for signal writes isn't syntactic sugar — it's a semantic marker that makes writes greppable and prevents accidental mutation outside event handlers.

None of this requires you to adopt a new language forever. The compiler emits readable JavaScript that targets a 200-line reactive runtime. The generated code uses createSignal, createComb, createEffect — patterns you already know from Solid, Preact Signals, or Vue's composition API. If you outgrow Comb, you can read the generated code, understand it, and maintain it by hand. The .comb file is a better authoring format, not a lock-in.

Primitives

signal — mutable state

signal count = 0;
signal name = "";
signal price: float = 9.99;

Type annotations are optional — the type is inferred from the initial value. Explicit types (signal x: int = 0;) are still supported and enable compile-time type checking (warnings). Types: int, string, bool, float.

Signals can only be written inside always blocks using <=, ++, --, +=, or -=:

always @(increment) {
  count++;           // sugar for count <= count + 1
  score += 10;       // sugar for score <= score + 10
}

comb — derived value

comb doubled = count * 2;
comb label = "Count: " + str(count);
comb isValid = len(name) >= 3 && contains(email, "@");

Combs are pure derivations. The compiler statically extracts all dependencies and verifies they exist. All branches are tracked (static union semantics) — even inside ternaries, both sides are registered as deps.

always @(event) — event-triggered block

always @(increment) {
  count <= count + 1;
}

always @(reset) {
  count <= 0;
  name <= "";
}

Fires when the named event is triggered (e.g. from a button @click). Writes use <= (non-blocking assignment). Multiple writes in one block are atomic — all commit together via batch().

always @(signal, ...) — sensitivity-triggered block

always @(celsius) {
  fahrenheit <= celsius * 9 / 5 + 32;
}

always @(width, height) {
  area <= width * height;
}

Auto-fires when any declared signal changes. The compiler verifies the sensitivity list: every signal read inside the block must be declared in the @(...) list. An undeclared read is a compile error. Self-triggering writes are also caught.

edgeCount / negedgeCount — reactive edge counting

comb alertCount = edgeCount(cpuHigh) + edgeCount(memHigh);

edgeCount(expr) returns a reactive value that automatically increments each time expr transitions false→true. No manual counter signal needed — the count is derived from event history. negedgeCount(expr) counts true→false transitions.

view — reactive DOM

view {
  <div class="counter">
    <h1>{label}</h1>
    <p class={isValid ? "valid" : "invalid"}>{message}</p>
    <button @click=increment>+</button>
    <input @bind=name />
    @if (count > 10) { <p>High!</p> }
    @for item in items { <li>{item}</li> }
  </div>
}

{expr} — reactive text interpolation. @click=event — event binding. @bind=signal — two-way input binding. @if/@for — conditional and list rendering. class={expr} — dynamic attributes. No virtual DOM — effects directly patch DOM nodes.

Directives

@if / @else — conditional rendering

@if (count > 0) {
  <p>Count is positive</p>
} @else {
  <p>Count is zero</p>
}

@for — list rendering

@for item in items {
  <li>{item}</li>
}

Keyed list rendering with efficient reconciliation:

@for item in items key=item.id {
  <div>{item.name}</div>
}

@bind — two-way binding

<input @bind=name />
<input type="range" min="0" max="255" @bind=r />

Binds the input value to a signal or cell. Updates are bidirectional — changing the input updates the signal, and changing the signal updates the input. Range/number inputs auto-coerce to Number.

Form Elements

All form elements support @bind for two-way binding:

<input @bind=name />
<textarea @bind=description></textarea>
<select @bind=category>
  <option value="a">Option A</option>
  <option value="b">Option B</option>
</select>
<input type="checkbox" @bind=agreed />
<input type="radio" name="size" value="small" @bind=selectedSize />

The compiler detects the element type and uses the appropriate property (value vs checked) and event (input vs change).

Assertions

assert always (count >= 0);
assert canSubmit == (usernameValid && emailValid);

assert always — checked on every reactive update (continuous invariant). assert expr — checked once at initialization. The test harness auto-evaluates assertions across generated input combinations.

Module Composition

module Child {
  input label: string = "hello";
  output clicks: int = 0;

  always @(click) {
    clicks <= clicks + 1;
  }

  view {
    <button @click=click>{label} ({clicks})</button>
  }
}

module App {
  signal childClicks: int = 0;

  view {
    <Child label="Click me" clicks:={childClicks} />
    <p>Total: {childClicks}</p>
  }
}

input — read-only inside the child, set by the parent via attributes. output — writable by the child, readable by the parent. := binds an output back to a parent signal (bidirectional wiring). Multiple modules compile together — the compiler builds a cross-module registry for verification.

Component Slots

Components accept child content via <slot />. Parent content between component tags is passed to the child and rendered at the slot position.

module Card {
  input title: string = "";
  view {
    <div class="card">
      <h3>{title}</h3>
      <div class="card-body">
        <slot />
      </div>
    </div>
  }
}

module App {
  view {
    <Card title="My Card">
      <p>Child content goes here</p>
    </Card>
  }
}

Functions

fn — custom functions

Functions are defined with fn name(params) -> returnType { body }. The return type is optional. The last expression in the body is the implicit return value (like Rust). Explicit return expr; is also supported.

fn clamp(value: int, min: int, max: int) -> int {
  value < min ? min : value > max ? max : value;
}

fn formatPrice(amount: float) -> string {
  "$" + str(round(amount * 100) / 100);
}

Method Calls

Array and string methods work as method calls:

comb names = users.map(|u| u.name);
comb active = users.filter(|u| u.active);
comb found = items.find(|item| item.id == targetId);
comb csv = names.join(", ");
comb hasAdmin = users.some(|u| u.role == "admin");

Supported methods include: map, filter, find, findIndex, some, every, includes, indexOf, join, flat, sort, reverse, push, pop, trim, split, replace, startsWith, endsWith, toUpperCase, toLowerCase, substring, charAt.

String Templates

comb greeting = `Hello, ${name}! You have ${count} items.`;
comb statusMsg = `Price: $${str(round(price * 100) / 100)}`;

Backtick strings with ${expr} interpolation, compiled to JS template literals.

Destructuring

always @(processData) {
  const { name, email } = userData;
  const [first, ...rest] = items;
  displayName <= name;
}

Object and array destructuring with const. Supports aliases ({ key: alias }) and rest patterns (...rest).

Try/Catch

always @(submit) {
  try {
    result <= processForm(data);
  } catch (e) {
    error <= "Something went wrong";
  }
}

Async Blocks

always @(loadUsers) {
  loading <= true;
  async {
    const response = await fetch("/api/users");
    const data = await response.json();
    users <= data;
    loading <= false;
  } catch {
    error <= "Failed to load";
    loading <= false;
  }
}

async { } blocks run asynchronously — the always block returns immediately and the async body executes in the background. Signal writes inside async blocks trigger new simulation cycles when they resolve. await is only valid inside async blocks.

Design Tokens

token primary: color = "#0052CC";
token radius: length = "8px";

A token is simultaneously a reactive signal and a CSS custom property (--primary, --radius). Changing the signal value at runtime updates the custom property. Use in styles via var(--primary).

Scoped Styles

style {
  .btn { background: var(--primary); padding: 8px; border-radius: var(--radius); }
  .label { font-weight: 600; }
}

Class names are auto-scoped per module using a deterministic hash (e.g. .btn becomes .btn_a1b2c). Styles are injected as a <style> element at mount time.

Propagator Networks

Bidirectional constraints using cells and the constraint keyword:

cell r: int = 255;
cell g: int = 0;
cell b: int = 0;
cell h: int = 0;
cell s: int = 100;
cell v: int = 100;

constraint rgbToHsv {
  (r, g, b) => {
    h <= rgbToHsv(r, g, b).h;
    s <= rgbToHsv(r, g, b).s;
    v <= rgbToHsv(r, g, b).v;
  }
}

constraint hsvToRgb {
  (h, s, v) => {
    r <= hsvToRgb(h, s, v).r;
    g <= hsvToRgb(h, s, v).g;
    b <= hsvToRgb(h, s, v).b;
  }
}

Cells are like signals but support merge semantics — multiple writers converge rather than conflict. Constraints define directional clauses: when inputs change, the body runs and writes outputs. The runtime uses createPropagator for convergent constraint propagation.

Enums

enum Phase { Red, Green, Yellow }

Used for FSM states. Enum values are available as Phase.Red, Phase.Green, etc.

The __graph Artifact

Every .comb file compiles to JavaScript that exports __graph — a JSON-serializable static dependency graph containing every node (signal, comb, cell, event, view binding, assertion) and every edge (data flow, trigger, write).

This single data structure powers:

ToolWhat it does
Circuit VisualizerRenders the reactive topology as a live diagram with pulse animations
Waveform DebuggerRecords signal traces over time, like a hardware logic analyzer
Circuit DiffCompares __graph across two versions to detect topology changes
Coverage TestingCombs are pure functions of their deps, so they ARE testable specs

Testing

Every compiled module exports a __test() function for headless testing:

// Headless test — no DOM needed
const t = __test();
t.signals.username.set("alice");
assert(t.combs.usernameValid() === true);
t.dispose();

The test harness instantiates the module headlessly, generates random inputs for all signals, evaluates all assert declarations, and reports boolean coverage (how many true/false combinations of combs were hit).
